# 5. 컴포넌트 쓰기

## 원칙: `lightning-*` 먼저

1. Salesforce 기본 컴포넌트(`lightning-*`)에 있으면 그것을 쓴다. Storybook **컴포넌트 / 기본**에 73개 전부가 브랜드로 그려져 있다
2. 없을 때만 밀버스 컴포넌트(**컴포넌트 / 밀버스 추가**)를 쓴다
3. 둘 다 없으면 프로젝트 컴포넌트를 만든다. 이름에 `milvus`를 쓰지 않는다(밀버스 전용 접두사)

## 패턴 명세: 화면은 이렇게 짠다

같은 `lightning-*`를 써도 모달마다 버튼 위치나 여는 방식이 달라질 수 있다. `init`이 놓는 `docs/milvus/patterns/`(패턴마다 파일 하나, 첫 파일은 `modal.md`)가 화면 패턴을 정하고, Claude는 LWC 화면을 만들기 전에 해당 패턴 파일을 읽는다. 명세와 다르게 하려면 Claude가 이유를 말하고 확인받는다.

- 지금은 **모달**만 있다: `LightningModal`을 상속하고 템플릿에는 `c-milvus-modal` 하나를 두어 안만 채운다. 제목은 가운데, 버튼은 오른쪽 아래 "비강조 → 강조" 순서, 크기는 `size`, 결과는 `this.close(result)`, 열 때는 `MyModal.open({ … })`
- 팀이 규칙을 바꾸거나 패턴(폼 레이아웃, 목록 툴바, 빈 상태, 오류 표시 등)을 더한다. 프로젝트 소유 파일이라 `update`가 덮어쓰지 않는다
- 공식 근거: [LightningModal](https://developer.salesforce.com/docs/platform/lightning-component-reference/guide/lightning-modal), [SLDS 2 Modals](https://www.lightningdesignsystem.com/components/modals/)

## 밀버스 컴포넌트

프로젝트 LWC의 html에서 `c-milvus-…` 태그로 쓴다. App Builder에는 나오지 않는다(`milvusBrandLoader`만 유틸리티 바에 노출). 각 컴포넌트는 브랜드 CSS를 스스로 불러온다. 모든 속성과 이벤트는 Storybook 문서 페이지의 controls와 실제 소스에 있다.

<table>
  <thead>
    <tr><th>컴포넌트</th><th>왜 있나</th><th>주요 속성</th><th>이벤트</th></tr>
  </thead>
  <tbody>
    <tr><td>`c-milvus-badge`</td><td>`lightning-badge`에 의미색(variant)이 없다</td><td>`label`, `variant`(default·inverse·lightest·success·warning·error·info), `icon-name`, `icon-position`</td><td>없음</td></tr>
    <tr><td>`c-milvus-button`</td><td>비교 예시. 평소엔 `lightning-button` 그대로 그린다. util.css에 `--milvus-button-custom: on`이 있을 때만 블루프린트 버튼</td><td>`label`, `variant`, `icon-name`, `icon-position`, `disabled`, `type`, `title`</td><td>`click`</td></tr>
    <tr><td>`c-milvus-multi-select`</td><td>검색해서 여러 개 고르기</td><td>`label`, `options`(`[{ label, value }]`), `value`(value 배열), `placeholder`, `required`, `disabled`</td><td>`change` → `detail.value`</td></tr>
    <tr><td>`c-milvus-notification`</td><td>SLDS Scoped Notification(화면 안 알림)에 공식 LWC가 없다. 닫기는 밀버스 확장</td><td>`variant`(info·success·warning·error), `message`, `dismissible`, 기본 slot</td><td>`close`(취소 가능)</td></tr>
    <tr><td>`c-milvus-modal`</td><td>모달마다 제목·버튼 자리가 달라지지 않게 하는 틀. `LightningModal`을 상속한 프로젝트 모달 안에 두고 기본 slot만 채운다. 닫기는 부모가 `this.close(result)`로 한다</td><td>`label`(제목, 가운데), `primary-label`(강조), `secondary-label`(비강조), `primary-variant`(brand·destructive), `primary-disabled`, `busy`, 기본 slot</td><td>`primary`, `secondary`</td></tr>
    <tr><td>`c-milvus-calendar`</td><td>공식 LWC는 날짜 선택만 있고 일정표가 없다</td><td>`view`(month·week), `value`(YYYY-MM-DD), `first-day-of-week`(0=일), `max-events-per-day`, `events`</td><td>`rangechange`, `eventselect`, `dayselect`</td></tr>
  </tbody>
</table>

### 예: 알림과 일정표를 쓰는 화면

```xml
<!-- teamSchedule.html -->
<template>
  <c-milvus-notification
    variant="warning"
    message="이번 주 릴리스 마감이 있습니다."
    dismissible
    onclose={handleClose}
  ></c-milvus-notification>

  <c-milvus-multi-select
    label="담당자"
    options={owners}
    value={selectedOwners}
    onchange={handleOwners}
  ></c-milvus-multi-select>

  <c-milvus-calendar
    view="month"
    events={events}
    onrangechange={handleRange}
    oneventselect={handleSelect}
  ></c-milvus-calendar>
</template>
```

```js
// teamSchedule.js
import { LightningElement } from "lwc";

export default class TeamSchedule extends LightningElement {
  owners = [
    { label: "김하나", value: "u1" },
    { label: "이두리", value: "u2" }
  ];
  selectedOwners = [];
  // id·title·start는 필수. start·end는 YYYY-MM-DD 또는 YYYY-MM-DDTHH:mm. 형식이 틀린 항목은 빠진다(console.warn)
  events = [
    { id: "1", title: "주간 회의", start: "2026-10-05T10:00" },
    { id: "2", title: "릴리스 마감", start: "2026-10-16", variant: "error" },
    { id: "3", title: "워크숍", start: "2026-10-27", end: "2026-10-29", variant: "warning" }
  ];

  handleOwners(event) {
    this.selectedOwners = event.detail.value;
  }

  handleRange(event) {
    // { view, start, end } — 보이는 범위가 바뀌면 이 범위의 일정을 다시 불러온다
    const { start, end } = event.detail;
    console.log("load", start, end);
  }

  handleSelect(event) {
    console.log("selected", event.detail.id);
  }

  handleClose() {
    // 닫힌 뒤 포커스는 부모가 정한다. 키보드 사용자를 위해 다음 작업 위치로 옮긴다
  }
}
```

- 밀버스 컴포넌트는 **표현 컴포넌트**다. `@wire`·Apex·LDS를 넣지 않는다. 데이터는 위처럼 부모(컨테이너)가 가져와 `events`·`options`로 넘긴다
- `close` 이벤트에서 `event.preventDefault()`를 부르면 알림이 닫히지 않는다(닫기 전 확인용)

## 프로젝트 컴포넌트에 브랜드 걸기

프로젝트 컴포넌트가 `--milvus-*`나 util.css 값을 읽어야 하면 `c/milvusScript`의 `loadBrand(this)`를 부른다. 브랜드 CSS(브리지 → util.css → override 순)를 문서에 넣고, 실패해도 화면을 막지 않는다.

```js
import { LightningElement } from "lwc";
import { loadBrand } from "c/milvusScript";

export default class OrderSummary extends LightningElement {
  connectedCallback() {
    loadBrand(this);
  }
}
```

앱에 `milvusBrandLoader`를 걸었으면([3장 7절](?path=/docs/런북-3-새-프로젝트에-적용--docs)) 그 앱의 페이지에는 이미 들어가 있다. 다른 앱·커뮤니티에서도 쓰일 컴포넌트라면 부르는 편이 안전하다.

- 먼저 [3장 7절](?path=/docs/런북-3-새-프로젝트에-적용--docs)의 Visualforce Settings를 켠다. `init --no-vf`로 만들었으면 VF 파일이 없다
- 위 조건(`showHeader="false"`, `applyBodyTag` 기본값)에서는 `<body>`에 `slds-scope`가 자동으로 붙는다(2026-10-14 측정). `applyBodyTag`·`applyHtmlTag`를 `false`로 두면 `slds-scope`를 직접 넣는다
- **미확인:** `showHeader="true"` 페이지의 `slds-scope`, Lightning Out에서 `rangechange`·`eventselect` 같은 밀버스 이벤트를 VF 스크립트로 받을 수 있는지, Lightning Out 2.0을 VF에서 쓰는 방법
