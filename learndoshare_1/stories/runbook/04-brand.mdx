# 4. 브랜드 바꾸기

브랜드 요청은 Storybook **시작하기 / 브랜드 명세** 페이지에 쓰고, Claude Code가 반영한다. 기본은 Salesforce 기본 모양에 브랜드 색·로고만 바꾼 것이다. 모양은 요청한 만큼만 바꾼다.

## 명세 페이지의 네 칸

모두 선택이다. 다 채우지 않아도 된다. 빈 칸은 파일에 적지 않는다.

<table>
  <thead>
    <tr><th>칸</th><th>쓰는 것</th><th>바뀌는 곳</th><th>알아 둘 것</th></tr>
  </thead>
  <tbody>
    <tr><td>브랜드 색</td><td>hex 하나. 예: `#2E7D32`</td><td>BrandingSet `BRAND_COLOR`</td><td>입력하면 버튼 색(50단계)·링크 색(40단계)과 흰색 대비가 바로 계산된다. 버튼에는 입력한 색이 아니라 50단계가 칠해진다</td></tr>
    <tr><td>로고</td><td>프로젝트 루트 기준 파일 경로. 예: `assets/logo.png`</td><td>`contentassets/<이름>Logo.asset`, BrandingSet `BRAND_IMAGE`</td><td></td></tr>
    <tr><td>피드백 색</td><td>성공·경고·오류·정보 칸마다 글자색·배경색</td><td>`milvusBrand.css`의 피드백 hook</td><td>글자색은 배경 위와 흰색 위에서 모두 4.5:1 이상이어야 한다</td></tr>
    <tr><td>디자인 명세</td><td>무엇이든 붙여 넣는다</td><td>Claude가 "바꿀 수 있는 것" 항목으로 나눠 반영</td><td>이전에 저장한 세부 요청과 겹치면 디자인 명세가 우선한다</td></tr>
  </tbody>
</table>

페이지 아래 **바꿀 수 있는 것**(모서리, 밀도, 글자, 바탕·면 색, 그림자 …)은 입력 칸이 없는 참고 목록이다. 지금 값과 한계를 보고, 바꾸고 싶은 것은 디자인 명세에 항목 이름과 함께 적는다. **바꿀 수 없는 것**은 맨 아래에 있다.

저장이 안 되는 환경(정적 빌드)이면 같은 내용을 Claude 채팅에 직접 쓴다.

## 디자인 명세에 붙여 넣는 예

**자연어**

```text
각지고 단단한 업무용 느낌, 촘촘하게.
회색은 쿨그레이, 카드 그림자는 없애 줘.
```

**다른 디자인 시스템 문서의 표** (복사한 그대로)

```text
<table>
  <thead>
    <tr><th>토큰</th><th>값</th></tr>
  </thead>
  <tbody>
    <tr><td>radius-sm</td><td>4px</td></tr>
    <tr><td>radius-md</td><td>8px</td></tr>
    <tr><td>gray-100</td><td>#F4F5F7</td></tr>
    <tr><td>text-muted</td><td>#6B778C</td></tr>
  </tbody>
</table>
```

**피그마 토큰 JSON** (Export modes 등)

```json
{
  "color": {
    "surface": { "page": { "$value": "#F8F8F8" }, "card": { "$value": "#FFFFFF" } },
    "text": { "primary": { "$value": "#1D1C1D" }, "secondary": { "$value": "#616061" } }
  },
  "radius": { "md": { "$value": "8px" } }
}
```

**사이트 주소**

```text
https://example.com 느낌으로. 바탕은 밝은 회색, 모서리는 둥글게.
```

주소만 주면 Claude가 그 사이트에서 읽은 값은 **추정**으로 표시한다. 정확한 값이 필요하면 표나 토큰을 붙여 넣는다.

## 예시: 슬랙에서 착안한 브랜드

공개된 슬랙 화면의 색을 참고해 만든 실습용 예다. 슬랙 로고는 상표라 쓰지 않는다. 모서리·그림자는 공개 자료로 확인하지 않은 **추정값**이다.

**명세 페이지 입력**

<table>
  <thead>
    <tr><th>칸</th><th>입력</th></tr>
  </thead>
  <tbody>
    <tr><td>브랜드 색</td><td>`#4A154B`</td></tr>
    <tr><td>로고</td><td>비움(팀 실습용 자체 로고가 있으면 그 경로)</td></tr>
    <tr><td>피드백 색</td><td>성공 글자 `#007A5A` · 오류 글자 `#921D21` · 경고 배경 `#ECB22E`, 글자 `#1D1C1D`</td></tr>
    <tr><td>디자인 명세</td><td>아래 텍스트</td></tr>
  </tbody>
</table>

```text
슬랙에서 착안한 업무용 메신저 느낌.
- 페이지 바탕 #F8F8F8, 카드 #FFFFFF
- 본문 글자 #1D1C1D, 보조 글자 #616061
- 구분선 #DDDDDD
- 툴팁 배경 #1D1C1D
- 상단 헤더 #3F0E40
- 모서리: 버튼·입력 약 8px, 카드 8px (추정)
- 그림자: 카드는 아주 옅게 (추정)
- 초록 전송 버튼
- 글꼴 Lato
```

**Claude가 나눌 곳 (참고)**

  <thead>
    <tr><th>요구</th><th>쓰는 곳</th><th>결과</th></tr>
  </thead>
  <tbody>

    <tr><td>본문·보조 글자</td><td>`--slds-g-color-on-surface-3`, `--slds-g-color-on-surface-1`</td><td>됨. 글자·면 4.5:1 검사</td></tr>

    <tr><td>모서리·그림자</td><td>`--slds-g-radius-border-*`, 버튼·입력·카드 s hook, `--slds-g-shadow-*`</td><td>됨(추정값으로)</td></tr>

  </tbody>
</table>

## 명세 표 읽는 법과 승인

"브랜드 요청 반영해줘"라고 하면 Claude는 파일을 고치기 전에 이런 표를 보여 준다.

<table>
  <thead>
    <tr><th>칸</th><th>볼 것</th></tr>
  </thead>
  <tbody>
    <tr><td>항목</td><td>모서리, 바탕·면 색 같은 명세 항목</td></tr>
    <tr><td>적용 값</td><td>실제로 넣을 값. hex, rem, `light-dark()` 쌍(다크 모드 값 포함)</td></tr>
    <tr><td>쓰는 곳</td><td>파일과 hook·브리지 변수 이름. 판단 사다리의 어느 단계인지 알 수 있다</td></tr>
    <tr><td>출처</td><td>요청의 어느 문장, 어느 토큰에서 왔는지</td></tr>
    <tr><td>확정/추정</td><td>**추정**은 Claude가 정한 값이다. 원하는 값이 있으면 승인 전에 고쳐 달라고 한다</td></tr>
    <tr><td>반영하지 못하는 요구와 대안</td><td>바꿀 수 없는 것과 그 이유. override(공식 권고 밖)를 제안하면 위험을 알고 고른다</td></tr>
  </tbody>
</table>

- 고칠 것이 있으면 채팅으로 말하고 표를 다시 받는다. 맞으면 "승인"이라고 한다
- 반영 뒤 Storybook이 저절로 다시 그린다. 마음에 들지 않으면 "카드 그림자는 기본으로 되돌려줘"처럼 이어서 말한다
- 명세 페이지 없이 채팅으로 바로 시켜도 된다. 예: "브랜드 색을 신뢰감 있는 딥그린으로, 각지고 촘촘하게 해줘", "성공 색은 글자 #1B5E20, 배경 #E8F5E9로", "모달을 더 넓게"
