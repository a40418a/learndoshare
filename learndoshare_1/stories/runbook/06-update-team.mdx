# 6. 업데이트와 팀원 합류

## 패키지 업데이트

```bash
pnpm add -D @a40418a/milvus-design-system@0.3.0
pnpm milvus update
pnpm milvus check
```

<table>
  <thead>
    <tr><th>`update`가 하는 일</th><th>하지 않는 일</th></tr>
  </thead>
  <tbody>
    <tr><td>관리 파일(밀버스 LWC, `milvusBridge.css`, `.claude/rules/milvus/design.md`, skill, hook)을 새 버전으로 바꾼다</td><td>소유 파일(`milvusBrand.css`, `milvusOverride.css`, `docs/milvus/patterns/`, BrandingSet 등)은 건드리지 않는다. 없는 소유 파일만 새로 놓는다(새 버전이 더한 패턴 파일)</td></tr>
    <tr><td>0.2.x 프로젝트를 0.3.0 배치로 옮긴다: 루트의 `milvus-patterns.md`·`milvus-brand-request.md`를 `docs/milvus/`로 내용 그대로 옮기고, 고치지 않은 `milvus-design.md`와 `CLAUDE.md`의 `@milvus-design.md` 줄을 지운다</td><td>옛 `milvus-design.md`를 고쳤으면 아무것도 바꾸지 않고 멈춘다(`--force`면 지운다). 새 위치에 이미 파일이 있으면 옛 파일을 옮기지 않고 알린다</td></tr>
    <tr><td>`.claude/settings.json`에 새 permissions·hook을 병합한다</td><td>생성 파일(`milvusVf.css`)은 덮지 않는다. `check`·`deploy`가 다시 만든다</td></tr>
    <tr><td>`milvus.config.json`의 버전과 sha256을 갱신한다</td><td>새 버전에 없는 관리 파일을 지우지 않는다. 목록에서만 빼고 알려 준다</td></tr>
  </tbody>
</table>

- **고친 관리 파일이 하나라도 있으면** 아무 파일도 바꾸지 않고 멈춘다. 파일마다 처음 달라진 줄을 보여 준다
- 고친 내용이 필요하면 다른 곳에 옮겨 둔 뒤 `pnpm milvus update --force`로 패키지 원본으로 덮어쓴다
- 바뀐 파일이 있으면 `pnpm milvus deploy`로 계획을 보고 org에 반영한다([3장 6절](?path=/docs/런북-3-새-프로젝트에-적용--docs))

**`milvus storybook`이 버전이 다르다고 멈추면** 패키지만 올리고 `update`를 하지 않은 것이다. 새 밀버스 컴포넌트가 프로젝트에 없어 스토리가 깨지므로 먼저 막는다. `pnpm milvus update`를 실행한다.

## 팀원이 프로젝트에 합류할 때

`init`은 프로젝트에 한 번만 한다. 결과 파일(`milvus.config.json`, `.claude/`, `force-app/` 아래 밀버스 파일, `pnpm-workspace.yaml`)은 커밋되어 있으므로 팀원은 `init`을 다시 하지 않는다.

1. [2. 준비](?path=/docs/런북-2-준비--docs)를 마친다: Node, pnpm, sf, `NODE_AUTH_TOKEN`, `~/.npmrc` 토큰 줄
2. 받고 설치한다

   ```bash
   git clone <저장소 주소>
   cd <프로젝트 폴더>
   pnpm install
   pnpm milvus --version
   ```

3. org에 로그인한다. 별칭은 `milvus.config.json`의 `targetOrg`와 같게 하거나, 배포할 때 `--target-org`로 준다

   ```bash
   sf org login web --alias my-org
   ```

4. 확인한다

   ```bash
   pnpm milvus check
   pnpm milvus storybook
   ```

5. Claude Code는 **이 프로젝트 폴더로** 세션을 열고 폴더 신뢰를 받아들인다. 그때부터 커밋된 hook(`milvus-check.mjs`)과 permissions가 적용된다

## 버전을 맞추는 법

- 패키지 버전은 `package.json`과 `pnpm-lock.yaml`이 정한다. 올리는 사람은 `pnpm add -D …@<버전>` → `pnpm milvus update` → `check` → 커밋까지 한 번에 하고 PR로 나눈다
- 팀원은 받은 뒤 `pnpm install`만 하면 된다. `update`는 이미 커밋된 결과라 다시 하지 않는다
