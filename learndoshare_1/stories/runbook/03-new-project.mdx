# 3. 새 프로젝트에 적용

[2. 준비](?path=/docs/런북-2-준비--docs)를 마친 뒤 순서대로 실행한다. 예시의 org 별칭은 `my-org`, 브랜드 이름은 `Demo`다. 이미 있는 SFDX 프로젝트라면 1단계를 건너뛰고 그 폴더에서 시작한다.

## 1. 프로젝트 만들고 설치

```bash
sf project generate --name milvus-demo
cd milvus-demo
printf '@a40418a:registry=https://npm.pkg.github.com\n' >> .npmrc
# pnpm 11만: 2장 4절의 pnpm-workspace.yaml
printf "minimumReleaseAgeExclude:\n  - '@a40418a/*'\nallowBuilds:\n  esbuild: true\n" > pnpm-workspace.yaml
pnpm add -D @a40418a/milvus-design-system
pnpm milvus --version
```

`--version`이 `0.2.3`(또는 그 뒤 버전)을 출력하면 된다. `sfdx-project.json`의 기본 패키지 폴더는 `force-app`이어야 한다(`init`이 확인한다).

## 2. `init`

```bash
pnpm milvus init --target-org my-org --brand Demo
```

<table>
  <thead>
    <tr><th>옵션</th><th>뜻</th></tr>
  </thead>
  <tbody>
    <tr><td>`--target-org <별칭>`</td><td>필수. 로그인을 확인하고 `milvus.config.json`에 기록한다</td></tr>
    <tr><td>`--brand <이름>`</td><td>새 브랜드 이름. 영문자로 시작하고 영문자·숫자·`_`만(한글 불가). 기본 색 `#0176D3`으로 시작한다</td></tr>
    <tr><td>`--from-org`</td><td>`--brand` 대신. org의 지금 활성 테마(SLDS 2)의 이름·색·로고를 가져온다</td></tr>
    <tr><td>`--no-vf`</td><td>Visualforce를 쓰지 않으면. VF 파일(`milvusVf.css`, `milvusHead`)을 만들지 않는다</td></tr>
  </tbody>
</table>

이미 있는 파일은 덮어쓰지 않고 "건너뛴 파일"로 알려 준다. 끝에 다음 단계가 출력된다.

## 3. Storybook과 브랜드 명세

```bash
pnpm milvus storybook
```

브라우저에서 **시작하기 / 브랜드 명세**를 열고 네 칸(브랜드 색, 로고, 피드백 색, 디자인 명세)에 요청을 쓴 뒤 **저장**한다. 모두 선택이다. 프로젝트 루트에 `milvus-brand-request.md`가 생긴다. 칸마다 쓰는 법은 [4. 브랜드 바꾸기](?path=/docs/런북-4-브랜드-바꾸기--docs)에 있다.

- 저장은 `pnpm milvus storybook`(localhost 개발 서버)에서만 된다. GitHub Pages 배포본에서는 입력이 꺼져 있다
- Storybook은 켜 둔다. 파일이 바뀌면 저절로 다시 그린다

## 4. Claude Code로 반영

**프로젝트 폴더(`milvus-demo`)로 연 세션**에서 말한다. 다른 폴더로 연 세션에는 이 프로젝트의 규칙(`CLAUDE.md`, permissions, hook)이 적용되지 않는다. 처음 열 때 폴더 신뢰를 받아들인다.

```text
브랜드 요청 반영해줘
```

1. Claude가 **브랜드 명세 표**(무엇을, 어느 파일의 어떤 hook으로)를 먼저 보여 준다. 파일은 아직 고치지 않는다
2. 표를 읽고 승인한다(읽는 법은 4장)
3. Claude가 BrandingSet과 `milvusBrand.css`를 고친다. 고칠 때마다 hook이 `check --style`로 규칙과 대비 4.5:1을 검사하고, 어기면 고칠 값을 돌려준다

## 5. 확인

```bash
pnpm milvus check
```

- `milvus check 통과`가 나와야 한다
- Storybook에서 툴바 🖌 **브랜드**로 기본 브랜드와 새 브랜드를 바꿔 같은 스토리를 비교한다
- **시작하기 / 반영 검사**에서 "반영 검사 시작"을 누르면 모든 컴포넌트에 닿는지 판정 표가 나온다(몇 분, 탭을 앞에 둔다)

## 6. 배포

활성 테마 변경은 **org 전체 사용자 화면**에 적용된다. 그래서 계획부터 본다.

```bash
pnpm milvus deploy
```

`--yes` 없이 실행하면 계획만 출력한다: 대상 org, 지금 활성 테마 → 새 활성 테마, 1단계 배포 목록, 경고. 터미널에서 직접 실행하면 `y/N`을 묻는다(기본 N). 계획을 확인했으면 실행한다.

```bash
pnpm milvus deploy --yes
```

- 1단계: 밀버스 메타데이터를 한 번에 올린다. 하나라도 실패하면 전부 롤백되고 테마를 바꾸지 않는다
- 2단계: 1단계가 성공했을 때만 활성 테마를 바꾼다
- Claude에게 "반영한 거 배포 계획 보여줘"라고 해도 된다. Claude는 채팅에서 승인받은 뒤에만 `--yes`를 실행하고, `permissions.ask`가 한 번 더 묻는다
- 테마 색은 브라우저를 새로고침한 뒤에 보인다. `--target-org`를 주면 `milvus.config.json`의 org 대신 그 org에 배포한다

## 7. 배포 뒤 사람이 할 일

메타데이터로 할 수 없어 `deploy`가 하지 않는다.

<table>
  <thead>
    <tr><th>할 일</th><th>방법</th><th>안 하면</th></tr>
  </thead>
  <tbody>
    <tr><td>앱 전체에 브랜드 걸기</td><td>Setup → App Manager → 앱 편집 → 유틸리티 바(Utility Items)에 `milvusBrandLoader` 추가 → **"앱이 열릴 때 백그라운드로 로드"**(Load in background when app opens) 체크. 앱마다 한다</td><td>밀버스 컴포넌트가 있는 페이지에만 브랜드 스타일이 걸리고, 표준 화면에는 테마 색만 들어온다</td></tr>
    <tr><td>VF를 쓰면</td><td>Setup → User Interface → **Visualforce Settings**의 "Use SLDS 2 for pages that include `<apex:slds>` when an SLDS 2 theme is active" 켜기</td><td>VF가 SLDS 1로 그려지고 `milvusBrand.css`가 효과가 없다</td></tr>
  </tbody>
</table>

로더는 유틸리티 바에 버튼으로 보인다. 라벨·아이콘은 App Manager에서 정한다. 패널을 열어도 아무것도 그리지 않는다.

## 만들어지는 파일 지도

**관리**: 밀버스가 관리한다. 직접 고치지 않고 `update`가 바꾼다(`milvus.config.json`에 sha256, Claude는 `permissions.deny`로 못 고친다) · **소유**: 프로젝트가 고친다(사람과 skill) · **생성**: CLI가 만든다
