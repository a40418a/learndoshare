# 런북: 밀버스 디자인 시스템 적용하기

Salesforce 프로젝트에 밀버스 디자인 시스템을 설치하고, 브랜드를 바꾸고, org에 배포하는 순서입니다. 위에서부터 차례로 따라 하세요. 기준 버전은 **0.3.0**입니다. Windows는 Git Bash 기준입니다.

## 1. 준비 (사람마다 한 번)

### 1-1. 프로그램 설치

- **Node** 22.18 이상: [nodejs.org](https://nodejs.org/)
- **pnpm**: [pnpm 설치 안내](https://pnpm.io/installation). `npm`·`npx`·`yarn`은 쓰지 마세요
- **Salesforce CLI**: [Salesforce CLI](https://developer.salesforce.com/tools/salesforcecli)

```bash
node -v
pnpm -v
sf --version
```

### 1-2. GitHub 토큰 만들기

패키지가 GitHub Packages에 있어서 설치할 때 토큰이 필요합니다.

1. GitHub → Settings → Developer settings → Personal access tokens → **Tokens (classic)** → Generate new token (classic)
2. 권한은 **`read:packages`** 하나만 고르세요. 만료일도 정하세요
3. 토큰 값은 파일·채팅·문서에 붙여 넣지 마세요. 아래처럼 환경 변수에만 두세요

### 1-3. 토큰을 환경 변수 `NODE_AUTH_TOKEN`에 넣기

**macOS** (키체인에 넣어 두고 터미널이 열릴 때 꺼내 씁니다)

```bash
security add-generic-password -a "$USER" -s milvus-npm-token -w
echo 'export NODE_AUTH_TOKEN="$(security find-generic-password -a "$USER" -s milvus-npm-token -w)"' >> ~/.zshrc
```

첫 줄을 실행하면 토큰을 입력하라고 나옵니다. 그다음 새 터미널을 여세요.

**Windows**

1. 시작 메뉴에서 **"계정의 환경 변수 편집"** 을 여세요
2. 사용자 변수 → **새로 만들기** → 이름 `NODE_AUTH_TOKEN`, 값에 토큰을 붙여 넣으세요
3. Git Bash·VS Code·Claude 앱을 모두 닫고 다시 여세요

### 1-4. `~/.npmrc`에 토큰 줄 넣기

```bash
grep -q npm.pkg.github.com ~/.npmrc 2>/dev/null || printf '//npm.pkg.github.com/:_authToken=${NODE_AUTH_TOKEN}\n' >> ~/.npmrc
```

확인하세요. `ok`가 나오면 됩니다.

```bash
printenv NODE_AUTH_TOKEN > /dev/null && echo ok
```

### 1-5. org 로그인

```bash
sf org login web --alias my-org
sf org list
```

- 별칭(`my-org`)은 3단계의 `--target-org`에 씁니다
- 연습은 개인 Developer Edition이나 스크래치 org에서 하세요. 배포하면 org 전체 사용자 화면이 바뀝니다
- `sf org display`, `sf org list --json`, `sf auth list --json`, `sf org open --url-only`는 쓰지 마세요. 액세스 토큰이 화면에 나옵니다

## 2. 설치

SFDX 프로젝트 폴더에서 실행하세요. 새로 만들려면 `sf project generate --name milvus-demo` 뒤 `cd milvus-demo`.

```bash
printf '@a40418a:registry=https://npm.pkg.github.com\n' >> .npmrc
```

**pnpm 11이면** (`pnpm -v`가 11 이상) 설치 전에 이 파일도 만드세요. pnpm 10이면 건너뛰세요.

```bash
printf "minimumReleaseAgeExclude:\n  - '@a40418a/*'\nallowBuilds:\n  esbuild: true\n" > pnpm-workspace.yaml
```

설치하고 버전을 확인하세요.

```bash
pnpm add -D @a40418a/milvus-design-system
pnpm milvus --version
```

## 3. init (프로젝트마다 한 번)

```bash
pnpm milvus init --target-org my-org --brand Demo
```

<table>
  <thead>
    <tr><th>옵션</th><th>쓰는 법</th></tr>
  </thead>
  <tbody>
    <tr><td>`--target-org`</td><td>1-5에서 정한 org 별칭 (필수)</td></tr>
    <tr><td>`--brand`</td><td>새 브랜드 이름. 영문자로 시작하고 영문자·숫자·`_`만 쓰세요</td></tr>
    <tr><td>`--from-org`</td><td>`--brand` 대신 쓰면 org의 지금 테마(색·로고)를 가져옵니다</td></tr>

끝나면 만든 파일과 다음 할 일이 나옵니다. 만든 파일은 모두 커밋하세요(`.milvus/` 폴더만 빼고).

## 4. 브랜드 요청 적기

```bash
pnpm milvus storybook
```

1. 브라우저에서 **시작하기 / 브랜드 명세**를 여세요
2. 바꾸고 싶은 칸만 적으세요. 빈 칸은 그대로 둡니다
3. **저장**을 누르세요. `docs/milvus/brand-request.md`가 생깁니다

<table>
  <thead>
    <tr><th>칸</th><th>적는 것</th></tr>
  </thead>
  <tbody>
    <tr><td>브랜드 색</td><td>hex 하나. 예: `#2E7D32`. 버튼에는 Salesforce가 글자가 잘 보이는 색으로 바꿔 칠합니다. 칸 아래에 실제 버튼 색이 나옵니다</td></tr>
    <tr><td>로고</td><td>프로젝트 폴더 기준 파일 경로. 예: `assets/logo.png`</td></tr>
    <tr><td>피드백 색</td><td>성공·경고·오류·정보의 글자색·배경색</td></tr>
    <tr><td>디자인 명세</td><td>무엇이든 붙여 넣으세요. 다른 디자인 시스템의 표, 피그마 토큰 JSON, 사이트 주소, 원하는 느낌</td></tr>
  </tbody>
</table>

디자인 명세 예:

```text
각지고 단단한 업무용 느낌, 촘촘하게.
회색은 쿨그레이, 카드 그림자는 없애 줘.
페이지 바탕 #F8F8F8, 본문 글자 #1D1C1D, 구분선 #DDDDDD
```

- 무엇을 바꿀 수 있는지는 페이지 아래 **바꿀 수 있는 것**을 펼쳐 보세요
- 글꼴, 상단 헤더 색, 토스트 시간 같은 것은 **바꿀 수 없는 것**에 있습니다
- Storybook은 켜 두세요. 파일이 바뀌면 화면이 저절로 다시 그려집니다

## 5. Claude Code로 반영

**프로젝트 폴더로 연** Claude Code 세션에서 말하세요. 다른 폴더로 열면 밀버스 규칙이 적용되지 않습니다. 처음 열 때 폴더 신뢰를 받아들이세요.

```text
브랜드 요청 반영해줘
```

1. Claude가 **브랜드 명세 표**를 먼저 보여 줍니다. 아직 파일은 고치지 않습니다
2. 표를 확인하세요. **추정**이라고 적힌 값은 Claude가 정한 값입니다. 원하는 값이 있으면 말하세요
3. 맞으면 "승인"이라고 하세요. Claude가 파일을 고치고 규칙을 스스로 검사합니다
4. Storybook 화면이 바뀝니다. 더 고치려면 "카드 그림자는 기본으로 되돌려줘"처럼 이어서 말하세요

명세 페이지 없이 바로 말해도 됩니다. 예: "브랜드 색을 딥그린으로, 각지고 촘촘하게 해줘"

## 6. 확인

```bash
pnpm milvus check
```

- `milvus check 통과`가 나와야 합니다
- Storybook 위 툴바 🖌 메뉴에서 브랜드를 바꿔 가며 같은 화면을 비교하세요
- **시작하기 / 반영 검사**에서 [반영 검사 시작]을 누르면 모든 컴포넌트에 닿는지 볼 수 있습니다(몇 분, 화면을 앞에 두세요)

## 7. 배포

> **배포하면 org 전체 사용자 화면이 바뀝니다.** 팀 공용 org나 고객 org에서는 담당자와 먼저 확인하세요.

먼저 계획을 보세요. 이 명령은 아무것도 바꾸지 않습니다.

```bash
pnpm milvus deploy
```

대상 org, 바뀌는 테마, 올릴 파일 목록을 확인했으면 실행하세요.

```bash
pnpm milvus deploy --yes
```

- 파일 하나라도 실패하면 전부 되돌리고 테마도 바꾸지 않습니다
- 끝나면 브라우저를 새로고침하세요
- Claude에게 "배포 계획 보여줘"라고 해도 됩니다. Claude는 채팅에서 승인을 받은 뒤에만 배포합니다

## 8. org에서 마무리 (배포 뒤 한 번)

**앱 전체에 브랜드 걸기** (앱마다)

1. Setup → **App Manager** → 앱 편집
2. **유틸리티 항목**에 `Milvus Brand Loader`를 추가하세요
3. **"앱이 열릴 때 백그라운드로 로드"** 를 체크하고 저장하세요

안 하면 밀버스 컴포넌트가 있는 페이지에만 브랜드가 걸리고, 다른 화면에는 테마 색만 들어갑니다.

**Visualforce를 쓰면**

Setup → User Interface → **Visualforce Settings**에서 "Use SLDS 2 for pages that include `<apex:slds>` when an SLDS 2 theme is active"를 켜세요. VF 페이지에는 `<c:milvusHead/>`를 한 줄 넣으세요.

## 9. 컴포넌트 쓰기

1. Storybook **컴포넌트 / 기본**에서 먼저 찾으세요. Salesforce 기본 컴포넌트(`lightning-*`)입니다
2. 없으면 **컴포넌트 / 밀버스 추가**를 쓰세요
3. 예제 아래 **Show code**를 눌러 코드를 복사하세요

  <thead>
    <tr><th>필요한 것</th><th>쓸 것</th></tr>
  </thead>
  <tbody>
    <tr><td>버튼, 입력, 표, 모달</td><td>`lightning-button`, `lightning-input`, `lightning-datatable`, `LightningModal`</td></tr>
    <tr><td>토스트</td><td>`lightning/toast`</td></tr>
    <tr><td>날짜 하나 고르기</td><td>`lightning-input type="date"`</td></tr>
    <tr><td>상태 뱃지</td><td>`c-milvus-badge`</td></tr>
    <tr><td>검색하며 여러 개 고르기</td><td>`c-milvus-multi-select`</td></tr>
    <tr><td>화면 안 안내 문구(닫기 가능)</td><td>`c-milvus-notification`</td></tr>

- 데이터는 부모 컴포넌트가 불러와 속성으로 넘기세요. 밀버스 컴포넌트 안에는 `@wire`·Apex를 넣지 않습니다
- 새로 만드는 컴포넌트 이름에는 `milvus`를 쓰지 마세요
- 모달 같은 화면은 `docs/milvus/patterns/`의 규칙을 따르세요. Claude도 이 파일을 읽고 만듭니다
- 직접 만든 컴포넌트에 브랜드 CSS가 필요하면 `connectedCallback`에서 `loadBrand(this)`를 부르세요

```js
import { LightningElement } from "lwc";
import { loadBrand } from "c/milvusScript";

export default class OrderSummary extends LightningElement {
  connectedCallback() {
    loadBrand(this);
  }
}
```

## 10. 새 버전으로 올리기

```bash
pnpm add -D @a40418a/milvus-design-system@0.3.0
pnpm milvus update
pnpm milvus check
```

- 올린 사람이 결과를 커밋하세요. 팀원은 받은 뒤 `pnpm install`만 하면 됩니다
- `update`가 멈추면 밀버스 파일을 직접 고친 것입니다. 고친 내용을 따로 옮겨 둔 뒤 `pnpm milvus update --force`로 되돌리세요
- 바뀐 파일이 있으면 7단계처럼 배포하세요

## 11. 팀원이 합류할 때

`init`은 다시 하지 마세요. 이미 커밋되어 있습니다.

1. 1단계 준비를 마치세요
2. 저장소를 받고 설치하세요

```bash
pnpm install
pnpm milvus --version
```

3. org에 로그인하세요. 별칭은 `milvus.config.json`의 `targetOrg`와 같게 하세요
4. `pnpm milvus check`가 통과하는지 보세요
5. Claude Code는 프로젝트 폴더로 열고 폴더 신뢰를 받아들이세요
