# 7. 문제 해결

다른 노트북(Windows, pnpm 11)과 리허설에서 실제로 겪은 것이다. 먼저 `pnpm milvus --version`으로 버전을 확인한다. Windows 문제 대부분은 0.2.3에서 고쳤다.

## 설치

<table>
  <thead>
    <tr><th>증상</th><th>원인</th><th>해결</th></tr>
  </thead>
  <tbody>
    <tr><td>설치가 `404` · `401` · `403`</td><td>`NODE_AUTH_TOKEN`이 비었거나 만료, `read:packages` 권한 없음, 또는 레지스트리 줄이 없음</td><td>프로젝트 `.npmrc`의 레지스트리 줄과 `~/.npmrc`의 토큰 줄 확인. 환경 변수를 새로 넣었으면 터미널을 다시 연다([2. 준비](?path=/docs/런북-2-준비--docs))</td></tr>
    <tr><td>`Ignored project-level auth setting … _authToken` 경고</td><td>pnpm 10.34.2·11.5.3부터 프로젝트 `.npmrc`의 `${…}` 토큰을 풀지 않는다</td><td>토큰 줄을 `~/.npmrc`로 옮긴다</td></tr>
    <tr><td>새 버전이 있는데 이전 버전이 설치됨 (pnpm 11)</td><td>`minimumReleaseAge` 기본 1440분</td><td>`pnpm-workspace.yaml`에 `minimumReleaseAgeExclude: ['@a40418a/*']`</td></tr>
    <tr><td>`ERR_PNPM_IGNORED_BUILDS: esbuild` (pnpm 11)</td><td>`strictDepBuilds` 기본 true</td><td>`pnpm-workspace.yaml`에 `allowBuilds: { esbuild: true }`</td></tr>
    <tr><td>`duplicated mapping key` (pnpm 11)</td><td>pnpm이 만든 `allowBuilds` 자리 밑에 같은 키를 덧붙임</td><td>파일을 2장 4절 내용으로 덮어쓴다(`>`)</td></tr>
    <tr><td>`Command "milvus" not found`</td><td>설치 전에 `pnpm milvus add …`처럼 milvus를 부름, 또는 다른 폴더</td><td>설치는 `pnpm add -D @a40418a/milvus-design-system`. 명령은 프로젝트 폴더에서</td></tr>
  </tbody>
</table>

    <tr><td>명세 페이지에서 저장이 꺼져 있음</td><td>GitHub Pages 같은 정적 빌드</td><td>`pnpm milvus storybook`(개발 서버)에서 연다. 안 되면 채팅에 직접 쓴다</td></tr>
