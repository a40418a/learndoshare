# 8. 함께 해 보기(실습)

팀이 같이 응용해 볼 과제다. 각자 해 보고 결과(캡처, 명세 표, 막힌 곳)를 나눈다.

## 안전 수칙 먼저

- **배포는 org 전체 화면을 바꾼다.** 활성 테마는 org에 하나뿐이고 모든 사용자에게 적용된다
- 실습은 **각자 개인 Developer Edition·스크래치 org**에서 하거나, **Storybook까지만** 한다. 팀 공용 org·고객 org에는 `pnpm milvus deploy --yes`를 하지 않는다
- `deploy`는 `--yes` 없이 계획만 볼 수 있다. 계획의 "대상 org"를 꼭 읽는다
- 화면을 나눌 때 org 도메인, 사용자 이름, 레코드의 전화·이메일은 가린다

## 과제 3. 밀버스 컴포넌트로 작은 화면

<table>
  <tbody>
    <tr><td>**목표**</td><td>표현/컨테이너 분리를 지키며 밀버스 컴포넌트를 쓴다</td></tr>
    <tr><td>**단계**</td><td>1. 프로젝트에 `teamSchedule` 같은 LWC를 만든다(이름에 `milvus`를 쓰지 않는다) 2. `c-milvus-notification`(닫기 가능)과 `c-milvus-calendar`를 넣는다([5장 예](?path=/docs/런북-5-컴포넌트-쓰기--docs)) 3. 일정은 부모가 배열로 넘긴다. `rangechange`의 `start`·`end`를 콘솔에 찍는다 4. 토스트가 필요하면 `lightning/toast`를 쓴다</td></tr>
    <tr><td>**확인 기준**</td><td>`pnpm milvus storybook`에서 브랜드를 바꾸면 알림·일정표 색이 따라 바뀐다. 키보드만으로 알림을 닫고 일정표 날짜를 옮길 수 있다. `pnpm lint`(프로젝트에 있으면) 통과</td></tr>
  </tbody>
</table>

여유가 있으면 개인 org에서 Lightning Live Preview(`sf lightning dev component`)로 같은 컴포넌트를 org 데이터와 함께 본다.

## 과제 4. 바꿀 수 없는 요청을 일부러 해 보기

  <tbody>

각자 받은 답을 모아 "Claude가 막은 이유"를 한 줄씩 정리한다. 막히지 않은 것이 있으면 세션을 프로젝트 폴더로 열었는지부터 본다([7. 문제 해결](?path=/docs/런북-7-문제-해결--docs)).

## 마치며

- 개인 org의 활성 테마를 원래대로 되돌릴 때는 대상 org와 명령을 먼저 확인한다. `deploy`에는 되돌리기 명령이 없다
- 막힌 곳, 바꾸고 싶은 규칙은 [저장소 이슈](https://github.com/a40418a/learndoshare/issues)로 남긴다
