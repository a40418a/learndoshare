# org 프로브 2차 (Task 9): LWC 배포, 브랜드 CSS가 닿는 범위, 유틸리티 바, VF (2026-10-09)

[설계](../specs/2026-10-08-milvus-package-design.md) 13장 "확인된 사실"과 14장 "미확인" 가운데 10/9에 org에서 잰 항목의 근거다. 1차 프로브(10/8)는 [2026-10-08/org-probe.md](2026-10-08/org-probe.md)에 있다. 이 결과로 사용자가 결정 D1~D4(설계 1장 10/9)를 내렸다.

- 대상: 이 저장소가 연결한 개발용 org(Developer Edition, 샌드박스 아님). 활성 테마 `Milvus_DesignSystem`(`SLDS_v2`, 다크 모드 꺼짐, `BRAND_COLOR` `#0176D3`). org ID, 주소, 사용자 이름, 배포 ID, 레코드 ID, 리소스 타임스탬프는 적지 않는다
- 메타데이터 API 버전: 67.0
- 프로브 파일과 측정 원본(결과 기록, 측정 스니펫)은 저장소 밖 임시 폴더에 두었고 옮기지 않았다. 아래 값은 결과 기록을 그대로 옮긴 것이다
- 측정: 내장 브라우저에서 측정 스니펫(`measure.js`)을 실행해 `getComputedStyle`로 읽었다. synthetic shadow는 `document.querySelector*`를 패치해 컴포넌트 안을 숨기므로 `TreeWalker`로 실제 DOM을 모두 돌고, open shadow root는 따로 들어간다. 결과에는 경로만 남기고 경로 안의 레코드 ID는 가렸다
- 표시: **(org 측정)** 화면에서 잰 것, **(공식 문서)** 문서를 직접 열어 확인한 것, **(로컬)** 이 저장소의 설치된 패키지에서 찾은 것, **미확인** 기록이 없는 것

## 3. 결과

### 3.1 `.ts` LWC 배포 **(org 측정, 공식 문서)**

- `.ts` LWC를 그대로 배포 → **실패**(원자적이라 남은 것 없음). org가 `.ts`를 타입 검사하며 `milvusProbe`의 `this.template`(LWC1539, 23:43·43:10)과 `this.dispatchEvent`(39:9)를 "type 'MilvusProbe'에 없음"으로 거부했다. `this.template`을 쓰지 않는 `milvusScript.ts`·`milvusProbeUtility.ts`에는 오류가 없었다
- 공식 문서: [LWC 개발자 가이드 "TypeScript (Developer Preview)"](https://developer.salesforce.com/docs/platform/lwc/guide/ts.html) (확인 2026-10-09). LWC 컴파일러는 TS를 컴파일하지 않으므로 배포 전에 TS를 JS로 변환해야 하고, 플랫폼은 TS를 저장하지 않는다
- 다시 배포: `typescript.transpileModule`로 `.js`를 만들고 `.forceignore`에 `**/*.ts`를 넣음 → **성공**. JS로 바꾼 `c/milvusScript` import와 `loadBrand`가 동작했다(세 link가 문서 head에 들어감)
- 10/8의 ".ts만 있는 번들 배포 성공"(설계 13장)은 문서에 없는 동작이었고 `this.template`을 쓰지 않는 번들이었다
- **판정:** 밀버스 LWC를 `.ts`로 쓰면 배포 전에 JS 변환이 필요하다 → 결정 D1(LWC는 JS), D4(변환 단계 없음)

### 3.2 기본 컴포넌트 렌더 모드 **(org 측정)**

- 프로브 화면의 `lightning-*` 호스트 90개 가운데 `data-render-mode` 속성이 있는 것이 0개 → 기본 컴포넌트는 전부 synthetic이다

### 3.3 클래스 규칙 도달 **(org 측정)**

- `milvusOverride`의 `.slds-button { border-radius: 0 }` → `lightning-button` 안의 `button.slds-button_brand` 반경 `0px`
- 프로브 밖 표준 헤더 버튼도 대부분 `0px`. 예외는 더 구체적인 선택자가 이기는 버튼이다: `appdev-panel-button` `4px`, `search-button` `8px`, 즐겨찾기 별 버튼 `240px`
- 브랜드 버튼 배경 `rgb(41, 118, 202)` = `#2976ca`(팔레트 50단계, 설계 13장과 같음)
- **판정:** 지금 org(synthetic)에서 `loadStyle`로 넣은 클래스 규칙은 기본 컴포넌트 안과 같은 화면의 표준 UI까지 닿는다. 선택자 우선순위에서 지는 곳은 남는다. `milvusBridge`·`milvusOverride`의 전제가 맞다

### 3.4 중립 색 **(org 측정)**

- `html` 배경 `rgb(255, 241, 219)`(`surface-2`)
- 전역 헤더·검색 입력·검색 버튼 배경이 `surface-container-1`
- 글자색 `on-surface-3`이 494개 요소, `border-1`이 7개 요소(전역 생성 메뉴, 패널)
- 카드 `article.slds-card` 배경 `surface-container-1`, 반경 20px(`radius-border-4` 기본값). 입력 배경 `surface-container-1`
- **판정:** util.css의 중립 색 hook이 LEX 표준 UI의 바탕·면·글자·테두리를 바꾼다. LEX가 페이지 바탕을 따로 칠하지 않는다

### 3.5 피드백 색 **(org 측정)**

- 프로브의 배지·알림(블루프린트): 브랜드 값
- 표준 시스템 경고 배너(`slds-notify_alert system-message level-warning`): 배경 `rgb(255, 213, 158)`, 글자 `rgb(92, 49, 0)`(`warning-container-1`, `on-warning-1`)
- `body`에 붙는 표준 토스트(`forceToastMessage`, `ShowToastEvent`): error·warning·success 모두 브랜드 피드백 색(container 배경, `on-*` 글자), 반경 8px. info는 동시에 3개까지만 보이는 제한 때문에 재지 못했다(**미확인**)
- **판정:** util.css의 피드백 색 hook이 LEX 표준 화면의 배너와 토스트에 반영된다

### 3.6 정의 없는 hook **(org 측정)**

- `--slds-g-color-accent-4`, `--slds-g-info-container-1`, `--slds-s-button-shadow-hover` → `:root`에서도, 기본 버튼 안에서도 빈 값. org도 정의하지 않는다(npm 번들에도 정의가 없음, 3.9)

### 3.7 유틸리티 바 백그라운드 로드 (설계 9.7) **(org 측정)**

- 유틸리티 바 배포 뒤 밀버스 디자인 시스템 앱의 리드 목록을 **새로 불러오고 유틸리티 패널은 열지 않음** → 콘솔 `[milvus] milvusProbeUtility connected`, milvus link 3개, `html` 배경 `surface-2`
- 대조: 판매 앱을 새로 불러옴 → milvus link 0개, `html` 배경 `rgb(243, 243, 243)`, hook은 org 기본값
- **판정:** 화면 없는 LWC 유틸리티 항목(`eager` = `true`)만으로 그 앱의 모든 페이지에 브랜드 CSS가 들어간다. 다른 앱에는 들어가지 않는다 → 결정 D3(`milvusBrandLoader`)
- 프로브는 FlexiPage XML의 decorator `eager`로 켰다. 이것이 App Manager의 "앱이 열릴 때 백그라운드로 로드"(Load in background when app opens) 체크와 같은 설정인지는 App Manager 화면에서 확인한 기록이 없다(**미확인**, 공식 샘플 형식만 확인)

- **판정:** 잰 표본에서 중립 색, 피드백 색, 모양, 간격 hook의 npm 기본값은 org 런타임 값과 같다. 다른 것은 브랜드 계열(`accent`, `brand-base`)뿐이고, org가 테마 브랜드 색으로 만든 팔레트를 넣기 때문이다. Storybook과 VF가 브랜드 팔레트(`--slds-r-color-brand-*`)를 직접 넣는 이유다
- 테마 `#0176D3`를 `lib/palette.ts`로 계산하면 40단계 `#1f5da1`, 50단계 `#2976ca`로 org 값과 같다. 70단계는 `#8cb1f7`로, org `accent-2`의 다크 값 `#87aef7`과 다르다. org 다크 모드가 꺼져 있어 화면에는 쓰이지 않는다. 원인은 **미확인**
- 1차 계획의 "Storybook 기본 브랜드 스토리에서 같은 스니펫으로 재기"는 하지 않고, 위처럼 설치된 CSS 파일에서 직접 비교했다
