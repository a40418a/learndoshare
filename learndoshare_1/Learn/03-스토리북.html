LEARN 03 · Phase 1·3 준비

스토리북

밀버스 컴포넌트를 org 없이 보여 주는 카탈로그가 Storybook이다. 웹 컴포넌트용 설정, 스토리 작성법, 브랜드를 바꿔 보는 툴바까지 우리 프로젝트에 필요한 만큼만 정리한다.

예상 1.5시간선행: 02 LWC · 07 pnpm2026-09-26 기준 storybook 최신 10.6.0

왜 알아야 하나

LWC 컴포넌트는 원래 org 안에서만 보인다. 디자이너, 기획자, 다른 프로젝트 개발자가 "버튼이 어떻게 생겼나"를 보려고 매번 org에 들어갈 수는 없다. Storybook은 컴포넌트를 상태별(스토리)로 늘어놓은 정적 사이트를 만들어 준다.

LWC 소스force-app/.../lwc/
→
Rollup 사전 컴파일dist/에 JS 생성
→
custom element 등록CustomElementConstructor로 태그 등록
→
Storybooklit html로 태그를 렌더링

Storybook 입장에서 우리 컴포넌트는 그냥 웹 컴포넌트(custom element)다. 그래서 프레임워크는 @storybook/web-components-vite를 쓰고, 스토리는 lit 템플릿으로 쓴다. LWC를 Storybook 안에서 직접 컴파일하지 않는 이유와 등록 방법은 04 통합에서 다룬다.

버전별 차이 (9 / 10)

2026-09-26 기준 storybook latest는 10.6.0이다 (next 태그 11.0.0-alpha.1, 9 계열 마지막 9.1.20). 인터넷 자료는 7~8 기준이 많아서 그대로 따라 하면 설치되지 않는 패키지가 나온다.

설치와 초기화

공식 문서는 npm create storybook@latest / npx storybook@latest init으로 안내한다. 우리는 pnpm 형태로 바꿔 실행한다 (07 pnpm 대응표).

# 생성기 방식
pnpm create storybook@latest

# 또는 설치 없이 CLI 일회성 실행
pnpm dlx storybook@latest init --type web_components --builder vite \
  --package-manager pnpm --features docs test a11y --yes --no-dev
플래그의미
--type web_components프로젝트 유형 자동 감지를 건너뛰고 웹 컴포넌트로 지정
--builder viteVite 빌더 사용. @storybook/web-components-vite는 Vite ≥ 5가 필요하다
--package-manager pnpm의존성 설치를 pnpm으로
--features docs test a11y문서, 테스트, 접근성 기능을 함께 구성
--yes질문에 기본값으로 답함
--no-dev설치 후 개발 서버를 자동으로 띄우지 않음
/** @type { import('@storybook/web-components-vite').StorybookConfig } */
const config = {
  framework: '@storybook/web-components-vite',
  stories: ['../stories/**/*.stories.js'],
  addons: ['@storybook/addon-docs', '@storybook/addon-a11y'],
  staticDirs: ['../public'],
};
export default config;   // 10은 ESM 전용: module.exports 쓰지 않는다

stories 경로와 addons 목록은 예시다. 초기화가 만든 파일을 기준으로 필요한 부분만 고친다.

pnpm hoisting 설정은 미리 넣지 않는다현재 Storybook 공식 문서에는 pnpm용 hoisting 권장 설정이 없다. 9~10에서 패키지가 통합되면서 문제가 크게 줄었다. "Cannot find module"이 실제로 났을 때만 07 pnpm · hoisting 문제 해결 순서대로 publicHoistPattern을 좁게 추가한다. 설치 중 esbuild 빌드 승인 요청이 나오면 pnpm approve-builds.

스토리 작성 (CSF3 + lit)

가장 작은 스토리

웹 컴포넌트 렌더러에서는 component에 태그 이름 문자열을 넣는다. render가 없으면 Storybook이 태그를 만들고 args를 넘겨 준다.

const meta = { component: 'demo-button' };
export default meta;

export const Primary = {
  args: { primary: true, label: 'Button' },
};

조금 더 갖춘 형태

import { html } from 'lit';

export default {
  title: 'Example/Button',
  component: 'demo-button',
  tags: ['autodocs'],              // addon-docs가 있으면 문서 페이지 자동 생성
  args: { label: 'Button', primary: false },
  argTypes: {
    label: { control: 'text' },
    primary: { control: 'boolean' },
  },
  render: (args) => html`<demo-button .label=${args.label} ?primary=${args.primary}></demo-button>`,
};

export const Primary = { args: { primary: true } };
export const Secondary = {};

lit 바인딩 네 가지

문법무엇을 설정하나예
x=${v}HTML attribute (항상 문자열)variant=${args.variant}
.x=${v}JS property (객체, 배열, 숫자 그대로).options=${args.options}
?x=${v}boolean attribute (true면 붙이고 false면 제거)?disabled=${args.disabled}
@x=${fn}이벤트 리스너@click=${args.onClick}
LWC의 @api 속성은 property 바인딩(.x=)으로@api로 공개한 값은 JS property로 넘기는 것이 가장 확실하다. 배열이나 객체는 attribute로 넘기면 문자열이 되어 버린다. 이름도 JS 이름 그대로 쓴다 (.iconName=).

미확인 CustomElementConstructor로 등록한 LWC 요소가 HTML attribute(icon-name="...")를 받아 @api property로 반영하는지, boolean attribute를 어떻게 해석하는지는 아직 시험하지 않았다. 확인 전까지는 property 바인딩만 쓴다.

decorator와 globals

globals는 모든 스토리가 공유하는 값(테마, 언어 등)이고, decorator는 스토리를 감싸는 함수다. 툴바에서 global을 바꾸면 decorator가 그 값을 읽어 스토리를 다시 감싼다. 브랜드 전환은 이 구조로 만든다.

import { html } from 'lit';

export default {
  globalTypes: {
    theme: {
      description: 'Global theme for components',
      toolbar: {
        title: 'Theme',
        icon: 'circlehollow',
        items: ['light', 'dark'],
        dynamicTitle: true,          // 툴바에 선택된 값을 표시
      },
    },
  },
  initialGlobals: { theme: 'light' },
  decorators: [
    (story, context) => html`<div data-theme=${context.globals.theme}>${story()}</div>`,
  ],
};
옛 자료의 globals, defaultValuepreview의 globals는 8.2에서 deprecated, 9.0에서 삭제되고 initialGlobals로 바뀌었다. 초기값도 더 이상 globalTypes.defaultValue에서 오지 않는다. globalTypes와 initialGlobals는 .storybook/preview.*에만 쓴다.

브랜드 decorator 예시

브랜드 폴더를 읽어 툴바 항목을 자동으로 만든다. Vite의 import.meta.glob은 파일 패턴에 맞는 모듈을 한 번에 가져오는 Vite 표준 기능이고, CSS에 ?inline을 붙이면 페이지에 자동 주입하지 않고 CSS 문자열만 받는다.

import { html } from 'lit';

// { '../brands/milvus/theme.json': { name, label, brandColor, headerBackground, hooks }, ... }
const themes = import.meta.glob('../brands/*/theme.json', { eager: true, import: 'default' });
// { '../brands/milvus/root.css': ':root { --milvus-... }', ... }
const rootCss = import.meta.glob('../brands/*/root.css', { query: '?inline', import: 'default', eager: true });

const brands = {};
for (const [path, theme] of Object.entries(themes)) {
  const dir = path.split('/')[2];                    // 'milvus'
  brands[dir] = { theme, css: rootCss[`../brands/${dir}/root.css`] ?? '' };
}
const first = Object.keys(brands)[0];

export default {
  globalTypes: {
    brand: {
      description: '브랜드 (org 테마 시뮬레이션)',
      toolbar: {
        title: 'Brand',
        icon: 'paintbrush',
        items: Object.entries(brands).map(([value, b]) => ({ value, title: b.theme.label })),
        dynamicTitle: true,
      },
    },
  },
  initialGlobals: { brand: first },
  decorators: [
    (story, context) => {
      const b = brands[context.globals.brand] ?? brands[first];
      // L1: org 색 → 래퍼의 인라인 CSS 변수
      const style = Object.entries(b.theme.hooks).map(([k, v]) => `${k}: ${v}`).join('; ');
      // L3: 선택된 브랜드의 root.css만 넣는다
      return html`<style>${b.css}</style><div class="milvus-brand" style=${style}>${story()}</div>`;
    },
  ],
};
  • CSS 변수는 상속되고 shadow DOM 경계도 넘어가므로, 래퍼에 넣은 값이 안쪽 컴포넌트까지 닿는다
  • root.css가 :root에 변수를 선언하면 래퍼가 아니라 문서 전체에 적용된다. 그래서 한 번에 선택된 브랜드 하나만 넣는다
  • JSON import: 'default', glob의 query: '?inline' 조합은 Vite 문서의 규칙(glob의 query 옵션, CSS ?inline)을 합친 것이다. 미확인 우리 저장소에서 실제로 돌려 보지는 않았다
  • paintbrush 아이콘 이름은 예시다. 미확인 공식 예제는 circlehollow를 쓴다
시뮬레이션이다툴바로 브랜드를 바꿔도 org는 바뀌지 않는다. 또 org가 자동으로 만드는 파생 색은 API로 읽히지 않으므로 hooks의 파생 색은 org와 미세하게 다를 수 있다 (05 테마 동기화).

인터랙션 테스트

스토리에 play 함수를 붙이면 렌더링 후 사용자 동작을 흉내 내고 결과를 검사한다. 도구는 storybook/test에서 가져온다.

import { html } from 'lit';
import { expect, fn, userEvent } from 'storybook/test';

export const Clicked = {
  args: { label: 'Save', onClick: fn() },
  render: (args) => html`<demo-button .label=${args.label} @click=${args.onClick}></demo-button>`,
  play: async ({ canvasElement, args }) => {
    await userEvent.click(canvasElement.querySelector('demo-button'));
    await expect(args.onClick).toHaveBeenCalled();
  },
};

미확인 컴포넌트 내부(shadow DOM 안쪽) 요소를 찾아 클릭하는 방법은 LWC 요소에서 아직 시험하지 않았다. 위 예시는 호스트 요소를 클릭한다.

화면 캡처 비교(시각 회귀 테스트)는 Storybook 팀의 Chromatic 서비스로 한다. 도입 여부는 미정이다.

사이드바 로고 (L2)

Storybook 화면 왼쪽 위 로고와 제목은 manager 쪽 테마로 바꾼다. 공식 문서 Theming 페이지 기준 import 경로는 storybook/manager-api와 storybook/theming이다.

import { addons } from 'storybook/manager-api';
import { create } from 'storybook/theming';

addons.setConfig({
  theme: create({
    base: 'light',                    // 필수. 나머지는 선택
    brandTitle: '밀버스 디자인 시스템',
    brandImage: './brand/logo.png',   // staticDirs { from: '../brands/milvus', to: '/brand' } 기준 예시
  }),
});

manager(사이드바)는 툴바의 브랜드 선택과 따로 돈다. 프로젝트별 Storybook은 브랜드가 하나로 정해지므로 생성할 때 그 브랜드의 logo.png를 연결하면 된다. 미확인 brandImage의 상대 경로가 배포 위치에 따라 어떻게 해석되는지는 빌드해서 확인해야 한다.

우리 프로젝트 적용

Storybook이 맡는 역할

Storybook은 새 프로젝트 워크플로의 ② ~ ④ 결과를 눈으로 확인하는 곳이다.

  1. 관리자가 org Setup에서 테마를 설정한다
  2. pnpm sync:theme이 색(L1 theme.json)과 로고(L2 logo.png)를 brands/<브랜드>/로 가져온다 → preview의 브랜드 decorator와 manager 로고에 반영
  3. 사용자가 원하는 느낌을 말하면 Claude가 brands/<브랜드>/root.css의 허용된 --milvus-* 변수만 고친다 (L3) → 같은 decorator로 바로 확인
  4. 사용자가 컴포넌트를 고르면 scripts/create-project.mjs --brand X --components badge,button --out <경로>가 그 브랜드·컴포넌트만 담은 Storybook을 만든다
층파일Storybook에서 반영되는 곳
L1 org 색brands/<브랜드>/theme.jsondecorator가 hooks를 래퍼 인라인 CSS 변수로
L2 로고brands/<브랜드>/logo.pngmanager.js의 brandImage
L3 사내 변수brands/<브랜드>/root.cssdecorator가 <style>로 삽입. --milvus-*만 선언, --slds-g-*는 읽기만
  • 스토리의 component는 CustomElementConstructor로 등록한 태그 이름이다. 태그 이름 규칙은 04 통합에서 정한다
  • @api 값은 property 바인딩(.x=)으로 넘긴다
  • 새 스토리를 만들 때 tags: ['autodocs']를 붙여 문서 페이지를 같이 만든다
  • 브랜드 decorator와 로고 설정은 계획이다. 현재 저장소에는 .storybook/, brands/, scripts/create-project.mjs가 아직 없다

스스로 점검

Q1. 블로그 예제가 @storybook/addon-essentials를 설치하라고 한다. 어떻게 하나?

설치하지 않는다. 9부터 삭제됐고 controls, actions, viewport 등은 코어에 들어 있다. 문서 기능이 필요하면 @storybook/addon-docs만 따로 추가한다.

Q2. 웹 컴포넌트 스토리의 component에는 무엇을 넣나?

태그 이름 문자열이다. 예: component: 'demo-button'.

Q3. 배열 options를 LWC 컴포넌트에 넘길 때 options=${args.options}와 .options=${args.options} 중 무엇을 쓰나? 왜?

.options=. 앞의 것은 attribute라 문자열로 바뀌고, .을 붙여야 JS property로 배열이 그대로 전달된다.

Q4. 툴바 초기값을 globalTypes.brand.defaultValue에 넣었는데 적용되지 않는다. 왜?

9.0부터 초기값은 preview의 initialGlobals에서 온다. initialGlobals: { brand: 'milvus' }처럼 쓴다.

Q5. 기획자에게 Storybook을 보여 주려면?

pnpm exec storybook build로 storybook-static을 만들어 정적 호스팅에 올리고 링크를 공유한다. 개발 서버나 org가 필요 없다.
